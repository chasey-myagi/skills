# issue-fix 产物模板

## issue.md（阶段 1）

```markdown
# Issue: #{id} {标题}

- 来源: {issue 链接}
- 现象: {错误描述，尽量原文引用}
- 复现条件: {输入 / 环境 / 步骤}
- 期望行为: {预期 X，实际 Y}
- 关联: {相关 PR / issue / 评论里的进展线索}
- 样本: {evidence/ 下的文件清单；0 个附件时明确写「无真实样本」}
```

## root_cause.md（阶段 4，审批门 1）

```markdown
# Root Cause: #{id} {issue 标题}

## 现象
{从 issue 提取的错误描述}

## 复现结果
- 复现方式: {命令 / 测试名，落在 results/ 的产物}
- 关键发现: {运行结果中具体哪里出了问题}

## 根因
{数据流追踪：输入 → 哪个阶段 → 什么发生了 → 导致什么}

### 证据
- 运行/调试产物: {日志、trace、中间产物里发现了什么}
- 代码 `file:line`: {代码逻辑问题}

## 结论
{一句话总结根因}
```

## plan.md（阶段 5，审批门 2）

```markdown
# Fix Plan: #{id}

## 根因（一句话）
{引用 root_cause.md 结论}

## 修复策略
{高层描述修复方向；如有备选方案，写明取舍}

## 代码变更清单
| 文件 | 修改内容 | 原因 |
|------|----------|------|
| {file} | ... | ... |

## 测试验证
- 红灯测试: {阶段 3 钉下的测试名/位置，修复后必须不加修改地翻绿}
- 新增用例: {test_name @ 位置}
- 检查规则: {描述，必须同时含正面验证（正确行为存在）与负面验证（错误行为不再出现）}
```
